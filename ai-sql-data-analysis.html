AI & DATA ANALYSIS

AI can write SQL. The real skill is knowing what to ask — and what the output means.

AI is making SQL easier to write. But writing a query is only one small part of data analysis. Planning the logic, testing the result and understanding what the numbers actually mean are becoming even more important.

Monika Verma22 September 20266 min read

One of the most useful things AI can do for a data analyst today is help write SQL. You can describe what you need in plain language and get a query in seconds. That is valuable — especially when you are working with unfamiliar syntax, complex joins or repetitive transformations.

But there is an important distinction: AI can help write the SQL. It cannot replace the analytical thinking behind the SQL.

SQL can be simple. The analysis is not.

Imagine the business asks: “Which marketing channel generated the most valuable customers last quarter?”

A query that groups customers by channel and sums revenue may be only a few lines long. But before writing those lines, an analyst has to make several decisions. What counts as a customer? Which date defines the quarter? Are we measuring first-touch channel, last-touch channel or the channel associated with the transaction? Should refunds be removed? Are duplicate orders possible?

Those decisions are the analysis. The SQL is simply how we express them.

A useful rule:

Do not ask AI to “write the query” until you can explain, in simple language, exactly what the query should calculate.

Plan the logic before asking AI for code

Before opening an AI tool, I find it useful to write down the analytical plan in plain English:

  • Business question: What decision are we trying to support?
  • Data grain: Is one row a user, order, session, campaign or event?
  • Sources: Which tables or systems contain the required data?
  • Relationships: How should those sources be joined?
  • Metrics: What exactly are we calculating?
  • Filters: Which dates, markets, products or customer groups are included?
  • Edge cases: What about nulls, duplicates, cancellations or missing tracking?

Once this is clear, AI becomes much more useful because you are giving it a specification rather than asking it to guess your business logic.

Use AI as a SQL drafting partner

For example, suppose the requirement is: calculate monthly revenue by marketing channel, exclude cancelled orders and only include completed orders from 2026.

SELECT
    DATE_TRUNC('month', order_date) AS month,
    marketing_channel,
    SUM(revenue) AS total_revenue
FROM orders
WHERE order_status = 'completed'
  AND order_date >= '2026-01-01'
GROUP BY 1, 2
ORDER BY 1, 3 DESC;

AI can generate something like this quickly. It can also explain the syntax, convert it between SQL dialects, suggest a window function or help simplify a complicated query.

That saves time. But a query being syntactically correct does not mean the analysis is correct.

The most important step: test the output

When AI generates SQL, I would never treat the first result as the final answer. The query needs to be tested like any other piece of analytical work.

Start small. Look at sample records. Check row counts before and after a join. Look for unexpected duplicates. Compare totals with an existing report. Check whether null values are being silently excluded. Pick a few customers or orders and manually verify that they appear in the correct segment.

A particularly common problem is a join that technically works but multiplies records. The query runs successfully, the dashboard looks polished — and the revenue is wrong.

AI may not know that happened unless you know what to test.

Understanding the output is now the differentiator

The more AI helps us write code, the more valuable interpretation becomes.

If revenue from one channel falls 25%, the analytical job is not finished when SQL returns -25%. We still need to ask why. Did traffic decline? Did conversion drop? Was tracking broken? Did the product mix change? Was one campaign paused? Is the comparison affected by seasonality?

This is where domain knowledge, curiosity and business context matter. A good analyst does not just retrieve a number. They understand the chain of logic behind it and know which follow-up questions to ask.

What changes for data analysts in the AI era?

I do not think the answer is to compete with AI on who can type SQL faster. The better opportunity is to become stronger at the parts AI cannot reliably own on its own: framing the problem, understanding data structure, defining the right metric, validating the logic and communicating what the result means.

SQL still matters. Advanced SQL still matters. Python, BI tools and data engineering still matter. But the value is increasingly in how we use those tools to reason about a business problem.

THE TAKEAWAY

Let AI accelerate the code — not replace the thinking.

Use AI to draft, explain, debug and improve SQL. But own the plan, the logic, the testing and the interpretation. That is what turns a simple query into trustworthy data analysis.
